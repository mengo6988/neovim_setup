# Neovim config

Lua-based, lazy.nvim managed. Entry point `init.lua` -> `require("mengo")`.

## Conventions

- One plugin per file under `lua/mengo/plugins/`, filename matching the plugin.
  Exception: a few files intentionally group a plugin family (`treesitter.lua`
  covers nvim-treesitter + context + textobjects + treesj; `plugins/init.lua`
  is the catch-all for small/misc plugins). Don't split those apart.
- Every plugin needs a lazy trigger (`event`/`ft`/`cmd`/`keys`) unless there's
  a real reason to load eagerly (colorscheme, statusline, treesitter itself).
  A plugin with no trigger and no comment explaining why is a bug, not a choice.
- Use `vim.g.border_style` for float borders (`hover`, `signature_help`,
  blink.cmp menus, etc.) instead of hardcoding `"rounded"`.
- Misc Lua that a keymap `require()`s (e.g. `yank.lua`, `open_link.lua`) lives
  directly under `lua/mengo/`. Scripts that just set up user commands/autocmds
  and are `require()`d once from `lua/mengo/init.lua` go in `lua/mengo/others/`.
- `lua/mengo/others/present.nvim` is a vendored, self-authored plugin (a
  learning project with its own tests), not a third-party dependency — don't
  replace it or point it at a registry.
- `lazy-lock.json` is generated by `:Lazy`. Don't hand-edit commit hashes;
  only prune an entry after confirming no spec references that plugin anymore.

## LSP / Mason

- `lua/mengo/plugins/lsp.lua` derives Mason's `ensure_installed` from local
  `servers`/`formatters` lists in that file — mason-tool-installer installs
  both. Add a new LSP server or formatter there, not as a separate
  `mason-lspconfig` `ensure_installed` entry, or the lists will drift.
- Formatter config lives in `plugins/init.lua` (conform). A formatter that
  should only run when a project opts in (like `prettier`) gets a `condition`
  that searches upward for that tool's config file; personal-machine tools
  (`stylua`) stay unconditional.

## Diagnostics

- `tiny-inline-diagnostic.nvim` owns diagnostic rendering and expects
  `virtual_text = false`. Don't re-enable stock `virtual_text` — toggle the
  plugin itself (see `<leader>vt` in `remap.lua`).

## Treesitter

- `nvim-treesitter` is pinned to the `main` (rewrite) branch. Anything that
  depends on it (`nvim-treesitter-textobjects`, textobject/motion plugins)
  must also target `main`, not `master` — the old API errors on the new parser.
